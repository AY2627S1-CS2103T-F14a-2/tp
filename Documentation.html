Documentation Guide

  • We use MarkBind to manage documentation.
  • The docs/ folder contains the source files for the documentation website.
  • To learn how set it up and maintain the project website, follow the guide [se-edu/guides] Working with Forked MarkBind sites for project documentation.

Local preview and diagram updates

Use Node.js 22.x (version 22.13 or newer) or Node.js 24.x, plus Java and Graphviz. From docs/, run npm ci once after pulling dependency changes, then npm run serve to preview the site. Both local builds and deployment use MarkBind 7.2.1, so the bundled PlantUML renderer is consistent (see course forum #722). Use npm ls markbind-cli to check the installed version.

GitHub and VS Code's standard Markdown previews do not render MarkBind's <puml> components. The DG therefore also includes ordinary <img> fallbacks from images/diagrams/. The website hides these fallbacks and renders the adjacent <puml> components, including during live preview.

After editing a diagram in diagrams/, run npm run build. The build generates the website and then refreshes the PNG fallbacks from the generated diagrams. Commit the updated PNGs together with the .puml sources. When adding a DG diagram, follow an existing <puml> / <img class="diagram-preview-fallback"> pair, using the same diagram filename, width and alternative text. Keep the .puml file as the editable source.

The exporter checks every PNG signature before updating any previews. Missing files or invalid signatures stop the export and retain the existing previews. Run npm test from docs/ to check the exporter's failure handling.
